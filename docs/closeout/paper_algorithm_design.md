# 3 多智能体博弈掼蛋算法设计与实现

## 3.1 算法总体框架

掼蛋是一类同时包含队内协作与队间对抗的不完全信息博弈。玩家既需要减少自身手牌，又需要根据队友和对手的出牌进展调整策略。能够压过当前桌面的动作，未必有利于后续出完；暂时过牌也可能为队友保留出牌机会。因此，决策需要综合考虑当前牌权、实际用牌成本、剩余手牌结构以及本队的出完顺序。

已有研究中，DanZero通过自我博弈生成训练样本，采用深度蒙特卡洛方法学习掼蛋策略[1]；DanZero+进一步研究了大动作空间条件下的策略训练[2]。本项目侧重于利用已有大语言模型的规则理解与策略分析能力，以DeepSeek Flash为核心，通过规则约束、公开信息分析和经验辅助组织决策过程。算法不进行模型参数训练，主要研究如何将牌局信息转换为模型能够比较的决策依据。

研究对象为四人、级牌为2、无需进贡的单局掼蛋，玩家1与玩家3同队，玩家2与玩家4同队。各玩家依据自身手牌和公开信息行动，不能直接获取队友或对手的未公开手牌。本文中的多智能体指四个玩家决策主体及其协作对抗关系，规则计算、知识检索和局面推演则作为决策辅助模块。

系统由规则引擎、智能体决策、知识检索和平台接入组成。规则引擎生成当前合法动作，信息分析模块整理手牌资源和公开历史，检索模块提供相关规则与经验，DeepSeek在展示候选中进行选择，最后由平台适配模块执行动作。设牌局状态为 \(s_t\)，玩家 \(i\)的公开观察为 \(o_t^i=\Omega_i(s_t)\)，合法动作集合为 \(\mathcal{A}_t^i\)，则动作选择与状态推进满足：

\[
a_t^i\in\mathcal{A}_t^i,\qquad s_{t+1}=T(s_t,a_t^i).
\]

其中，\(T\)为规则引擎定义的状态转移函数。该框架将规则判断与策略判断分开，使模型能够比较合法动作的价值，同时由引擎约束实际执行。

## 3.2 规则约束与公开信息表示

规则引擎使用Python实现，负责牌型识别、合法动作生成、压制比较、状态推进和终局判定。牌局使用两副扑克牌，共108张，每名玩家初始持有27张。引擎统一处理单张、对子、三张、三带二、顺子、连对、钢板、炸弹、同花顺和天王炸，并处理级牌、逢人配及连续牌型边界。

逢人配能够使相同牌型对应不同的实际用牌方式，因此系统分别记录动作的声明牌与实体承载牌。声明牌用于识别和比较牌型，实体承载牌用于扣除本家实际支付的牌，通配信息说明逢人配替代的目标。这样，算法可以区分牌型相同但消耗不同的动作，例如自然成组出牌与使用逢人配补组出牌，为后续资源比较提供统一依据。

决策接口向智能体提供本家手牌、当前桌面、轮次信息、其他玩家的公开状态、出牌历史及合法动作。智能体只能从当前合法集合中返回动作编号，不能自行构造动作或访问其他玩家真实手牌。终局判定与Botzone裁判规则对齐，同队取得头游和二游时立即结束，否则在三游出现时确定终局。项目另行采用规则胜平负口径：头游与末游同队为平局，其余情况下头游所在队伍获胜；平台积分与该结果分开记录。

公开记牌以实体牌守恒为基础。设 \(P(c)\)为完整牌池中牌面 \(c\)的数量，\(H_i(c)\)为本家当前持有数量，\(E_t(c)\)为公开历史中已打出的实体数量，则未见牌数量为：

\[
U_t(c)=P(c)-H_i(c)-E_t(c).
\]

计数采用多重集语义，保留双副牌中相同牌面的重复数量，并依据实体承载牌扣除已出牌，避免把逢人配声明后的虚拟牌当作真实牌。未见牌池结合各家的剩余容量形成可能持牌范围，为当前压制与阻断分析提供参考。只有在历史完整、容量一致且实体牌守恒成立时，唯一归属才可作为确证信息；历史过牌本身不能证明某玩家没有特定牌型。

本家资源分析则根据每个合法动作的实体支付，比较出牌数量、清空的点数组、自然对子与三张的拆分、完整炸弹的损失，以及级牌、王、逢人配和同花顺路线的消耗与保留。该分析将即时减张与后续结构联系起来，使模型能够看到“当前出了多少牌”和“剩余牌是否更容易处理”之间的差异。本地启发式评分用于开局分析、策略路由和经验检索，作为辅助信息参与比较，不将其解释为训练所得的胜率。

## 3.3 基于DeepSeek的协作决策

模型决策的重点在于将公开事实、候选动作差异和队伍目标组织为可比较的信息。输入包括当前局面、手牌资源分析、公开记牌、候选关系、策略参考意图、相关规则与经验，以及符合条件的局面推演结果。输出采用动作编号与简短理由组成的JSON结构，动作编号必须对应展示候选中的原始合法动作。

由于逢人配替代及实体支付组合可能产生较多动作，系统首先整理合法候选，压缩重复表达并保留关键差异。候选展示上限为80项，保护过牌、直接出完以及炸弹、同花顺和天王炸等重要路线。普通牌型可以合并部分重复花色表达，涉及逢人配用途和同花顺资源时则保留必要差异。候选整理只改变模型接收的表示，展示动作始终能够追溯到引擎生成的原始合法动作。

候选描述将实际支付与后续资源联系起来。例如，一次出多张牌可能同时拆散多个牌组，而较少的出牌数量也可能清空难以处理的点数。跟牌分析进一步按照各候选的压制阈值、玩家行动顺序和剩余容量，整理公开条件下可能出现的应手。模型据此比较争取牌权所需的代价及后续机会，公开可能应手仍与对手实际持牌相区分。

队伍协作贯穿上述比较。队友控桌时，本家需要判断接牌是否能增加本队收益，避免无效消耗关键资源；对手临近出完时，则需要比较阻断的可行性与紧迫性。队友已经取得头游后，本家争取二游可形成双下，决策也应相应调整。系统根据余牌数量、完赛状态和出牌历史识别牌局阶段，形成快速出完、控制牌权、协助队友或阻断对手等参考意图，供模型结合当前事实重新判断。

为提供局面相关知识，项目借鉴检索增强生成将外部知识引入模型输入的思路[3]，建立本地规则库与经验库。规则库解释逢人配、牌型压制、接风和终局，经验库以适用条件、建议倾向和反例调整描述策略。检索依据阶段、首出或跟牌场景、队伍关系及资源特征筛选，再结合关键词排序。该实现采用本地标签与关键词检索，不涉及原RAG研究中的神经检索器训练。

检索结果作为判断依据参与动作比较。例如，保留控制资源需要与当前阻断、直接出完或收尾机会共同考虑，协助队友也需要判断本家接牌是否具有实际收益。通过明确经验条件和动作支付，系统把一般策略建议对应到当前候选，而不将经验直接转化为固定动作规则。正常局面下，DeepSeek承担主要策略选择，成功的合法模型选择不会被本地评分重新覆盖。

## 3.4 局面推演与决策辅助

公开记牌与经验能够解释当前资源，但部分决策还需要比较后续局面。项目针对信息确定程度不同的场景实现两类推演：公开确证残局计算，以及共同可行假设下的有界续局比较。

公开确证计算用于本家与另一名活动玩家构成的小规模残局。系统先检查公开历史、实体牌守恒和玩家容量，只有剩余手牌能够唯一确定，并经引擎核对状态与合法动作后，才进行精确搜索。搜索将本队规则胜、平、负分别记为1、0、−1，本队行动取较大值，对手行动取较小值，以计算对手最不利回应下能够保证的结果。同时记录合法后续中可到达的结果，区分存在获胜路径与能够保证获胜。

当前精确搜索限定总余牌不超过12张、单家不超过8张，并设置节点与时间预算，以适应在线决策。完整保胜证明可以形成模型调用前的直接选择；完成的其他根动作比较则提供给模型。预算耗尽时不使用未完成结论，转回原有决策路径。该设计将搜索用于条件明确的局面，并通过回退控制计算对整体运行的影响。

其他玩家手牌尚不能唯一确定时，系统从未见实体牌和公开容量生成至多两个可复现的可行分配。待比较动作共享这些分配，避免各动作分别采用有利假设；随后通过统一规则推进，使用清组和协同留控两种后续策略进行有限比较。模拟行动者仅依据该时点自身观察与合法动作决策，假设中的手牌不作为当前真实对手手牌提供给生产模型。

有界续局最多比较六条展示路线，每条在共同场景和两种策略下推进至多八步，比较继续出牌数量、再次领牌次数、紧迫对手的进展以及剩余控制与成组资源。不同场景出现相反方向时保留分歧，计算块未完整完成时整块撤回。其结果描述共同假设下的有限后果，为DeepSeek提供额外比较依据，不构成暗牌确证或保胜结论。

## 3.5 系统实现与平台接入

系统通过本地connector接入Botzone。平台请求被转换为统一公开观察与合法动作，智能体返回原始动作编号后，适配器将实体牌和通配声明编码为平台响应。动作发送与执行确认分别管理，只有达到平台响应确认边界后，才提交相应状态与确认记录，从而保持模型选择、引擎动作和平台执行的一致性。

客户端检查模型输出结构及候选归属，智能体和适配器进一步校验原始动作合法性。仅能过牌、能够一次出完以及已有完整残局证明等明确情况可在调用模型前本地处理；其余局面交由DeepSeek比较。模型超时、异常或返回无效动作时，从原合法集合中选择回退动作。系统分别管理网络读取超时与整次决策期限，并隔离超时后的晚到结果。

实现验证围绕牌型与轮转规则、公开信息守恒、候选追溯、动作编码和执行确认展开。逐局记录进一步支持核对实际观察、展示候选、所选动作及确认状态，供运行诊断和实战分析使用。包含手牌与模型请求上下文的记录按私有证据管理，不将凭据和完整模型推理文本写入共享材料。

上述实现完成了从局面获取、信息分析、模型选择到动作执行的决策流程，并接入Botzone四人单局环境。规则约束提供统一动作空间，资源分析与经验检索组织判断依据，两类局面推演补充后续比较，运行校验与合法回退支持在线执行，共同构成以DeepSeek Flash为核心的协作对抗决策系统。

## 3.6 实战测试与结果分析

为观察最终系统在真实对局中的运行表现，拟在Botzone开展20局测试，双方使用统一的Flash模型，并登记各自程序版本、模型参数、所控席位及对手条件。第一批本方队伍使用1、3席，计划10局；第二批交换至2、4席，计划10局。测试期间保持策略条件一致，必要的运行修复按实际版本分段记录，同一对局的双方记录合并为一个样本。

测试分别统计项目规则胜平负与Botzone平台积分，记录有效完局、结果未知及中止异常，并结合超时和回退情况分析运行表现。规则结果可以确认时统计胜、平、负比例；信息不足时保留未知项，列明统计分母。平台正分比例与平均积分在相应记录完整时另行计算，避免混淆两种评价口径。

典型局面分析结合对局图片、公开动作和经核对的资源变化，讨论队友协作、紧迫阻断及实际支付的取舍。测试结果用于描述统一模型条件下系统的实际表现，相关模块的独立收益需要有对应对照才能判断。
