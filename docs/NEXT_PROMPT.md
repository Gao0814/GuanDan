## 已核对事实与目标

第 22 局首手 K 为 `local_shortcut`，实际由 `OpeningFormulaStrategy.analyze_action()` 的 ID 在 `DeepSeekAIAgent.select_action()` 中直接返回，未发模型请求。所有者现明确要求：来源化开局公式是**高优先级、可被推翻的模型前建议**，DeepSeek 尽可能负责真实取舍，不因公式给出合法 ID 就跳过模型。原有强制 pass、立即出完及公开手牌唯一且可证明的残局捷径按其已批准边界保留。第 22 局单 3 与单 K 的结构摘要均为出后约 12 组、4 孤张；单 3 参与合法 `A-2-3-4-5` 顺子，但出该顺子会拆四张 4 自然炸、A/2 三张及 5 对，余下三张 4、A/2 对子和单 5。不能把“3 参与顺子”直接当作保留 3 的充分证据，也不能为这局硬编码必须出 3。

同局第五次本家决策在模型 timeout 后由 `deepseek_rule_fallback` 出自然 `778899`，把 8/9 三张拆成单张；同一合法动作列表有自然 `888999` 钢板，公开余组/孤张事实更好。现有失败路径调用冻结 RuleBased selector，同张数/通配成本时按牌型名称排序。该局本队胜；这些事实只证明回退缺少结构比较，不能证明另一手必胜。决策约在开始后 114 秒触发 timeout，再约 2 秒获 ACK，符合 119 秒总预算扣 5 秒响应预留；不要通过盲目延长期限解决。

本任务建立连贯决策链：开局公式产生带来源条件和公开反例的优先建议，让建议原始合法 ID 与重要竞争路线进入最终最多 80 项候选及模型请求；成功模型返回的原始合法 ID 保留，不能后置强制改牌。建议只在来源条件确实适用时才以强语气出现；含糊或高成本取舍要展示双方，不把所有合法组合成员都视为值得保留的结构。若模型失败、超时或返回无效 ID，才在有限剩余时间内选合法回退动作，比较出牌量、出后余组/孤张、拆同点组和控制/通配消耗，避免同张数时被牌型字符串顺序支配。终局/公开紧急/队友控桌等反例与时间预算必须保留；不改变引擎规则、Botzone ACK、模型请求期限或历史冻结评测 selector 的语义。具体表示与接线由代码调查决定。

## 验收

- 用引擎生成的完整 108 张合法四人起局及类比反例，验证公式建议被送入默认 Botzone factory 的禁网实际 Request，推荐与竞争候选双端可见并闭环；模型 fake 返回与公式不同的展示原始 ID 时仍为 `source=model` 且不被改牌。特别核对“低点单张参与破坏性顺子”与“真正低成本自然顺子”两类情况，不能只为第 22 局牌点、seed、ID 编写旁路；保持来源 B/C 级条件和开局关系门槛。
- 用完整引擎局与反例、禁网 timeout/无效响应 fake 走真实失败路径：同张数、同通配成本而余牌结构明确有别时不再仅靠牌型名字排序；强制 pass、立即出完、公开紧急和结构不明时仍及时返回合法原始 ID。成功模型路径不进入这套回退。必要时只读第 22 局精确证据作对照，不能把现场选择变化等同于收益。
- 同机测量开局建议组装与密集候选、失败回退的本地耗时，并说明 119 秒决策期限与 5 秒预留内如何及时响应。真实 DeepSeek、Botzone 请求数应为 0；禁网 fake 只证明接线与机制，不证明策略或胜率提升。
- 运行定向、主规则、适用全量 `unittest` 与 `git diff --check`。所有者现场 connector 若影响旧 Windows 进程测试，准确报告，不为跑绿而停机或放宽断言。提交前反补丁自检：是否新增牌点/牌型特判、建议是否只进文字却没进最终候选、成功模型是否被覆盖、类比完整牌局能否自然工作。只提交本任务业务代码/tests，报告 commit、最终 Git status 和当前范围内剩余风险。
