# M8 Coding：普通牌型花色压缩与同花顺/逢人配成本

先读 `AGENTS.md`、适用项目 Skills、`docs/CLEAN_HANDOFF.md`、`docs/PLAN.md` 顶部、`docs/INVARIANTS.md`、`docs/CODING_BOUNDARY.md`，核对 Git status、HEAD、相关代码/tests。只修改并提交本任务业务代码/tests。所有者自行操作真实 Botzone；不得启停页面或 connector、修改现场 evidence、读取 `.env` 或持久化模型自由文本。

## 已核对事实与目标

目前 `DeepSeekClient._action_signature` 将实体 `carrier_cards` 花色纳入普通动作签名；`_action_summary_entry` 在普通候选中仍打印带花色的 `carrier_cards`。第 27 局末步同点自然单 9 的两个实体 ID 与 pass 均进请求，重复占用策略展示位。普通牌型的比较主要取决于点数；实体花色对策略仍可能通过**出后同花顺路线**和**红桃级牌逢人配身份/用途**产生差异。现有 M4 等关系有部分资源文案，但未系统地给普通候选说明这些差异。请求缩短不自动证明模型更快或更强。

本任务建立一套可复用的模型前普通动作投影：用完整实体手牌和原始 canonical 动作先计算出前、出后的同花顺可行路线（含逢人配）及逢人配资源，再将其余普通牌型尽量按点数描述。两个不同花色的普通载体仅在声明牌型/点数、出后同花顺机会、逢人配资源和相关余牌策略事实等价时共用一个真实原始 ID 代表；即使整手仍有其他同花顺，也可压缩真正等价的动作。若花色选择会拆/保留不同同花顺路线，或动作消耗红桃 2 的当前/后续逢人配用途，应保留可区分的原始候选，并在实际模型输入中明确列出对应 ID 的资源成本。成本是可权衡的提示，紧急阻断、立即出完和其他合法收益可以使模型选择高成本路线。

即使 `wildcard_count=0`，承载牌中的红桃级牌 `2H` 也不能当普通同点牌折叠。底层必须保留实体花色记牌、108 张守恒、其他玩家可能的同花顺资源、完整 `legal_actions()` 和真实 `carrier_cards`；只压缩 AI 的策略候选及显示，不改引擎合法性或动作 ID。推荐、关系两端、关键压制动作和 `pass` 仍须从原始合法列表追溯并在最终最多 80 个展示候选中闭环。DeepSeek 对真实取舍仍是主要决策者，成功返回的展示中原始合法 ID 不作策略后置覆盖。

## 验收

- 以引擎完整初始牌局、跟牌局和较密集候选状态复算：统计 raw/最终候选、同点花色重复占位、普通候选请求字符/UTF-8 字节及牌型覆盖，和当前 HEAD 同状态比较。证明压缩发生在真实默认 Botzone factory 请求，不只是辅助函数或合成单例；不要把缩短请求推断为真实延迟或胜率收益。
- 构造不同点数的完整合法类比局及反例：本家无同花顺；本家有同花顺但两载体出后资源等价；同点不同花色会拆掉/保留不同同花顺（含逢人配补齐）；普通自然动作与 `2H` 自然/通配使用。检查实际请求里资源损失对应原始 ID 可见，普通等价动作只保留真实代表，非等价动作不得误并。不能按第 27 局的 9、seed 或固定 ID 特判。
- 禁网 fake transport 验证推荐和完整关系端点都在最终候选内；模型返回任一展示 ID 后仍是同一原始合法 ID、`source=model`。保留炸弹、同花顺、天王炸、pass 与立即出完路径；格式化/投影异常时有界退回原有合法候选。原始 observation、公开历史、记牌器花色和引擎 canonical 动作均不被压缩视图改写。
- 测量本地投影耗时，确认不会吃掉 119 秒决策及 5 秒响应预留。运行定向、主规则和适用全量 `unittest`、`git diff --check`。真实 DeepSeek、Botzone/connector/browser 请求数为 0。所有者现场进程若干扰 Windows 进程探测测试，准确报告，不停止进程或放宽有效断言。
- 提交前做反补丁自检：检查是否出现按牌点/牌型逐个加白名单、重复花色映射、仅打印 rank 而未压缩候选、未保护资源差异或推荐/关系闭环。仅提交本任务业务代码/tests，报告实际验证层级、commit、最终 Git status 和当前范围内真实剩余风险。
