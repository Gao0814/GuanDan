## 实现范围

1. system可采用“擅长掼蛋的策略专家”角色，实际职责写清：以本队本局规则胜负为目标，从给定候选选择原始合法ID；比较本次支付、余手出路和以后重新取得牌权的条件。角色称号不作为效果证据。保持既有JSON协议，不新增长推理要求或另一次评估调用。
2. 默认实际factory请求撤去手牌总分、结构/控制/潜力分、强弱评级及相应主观评语，替换为独立【我的剩余手牌】。从当前my_info.hand_cards完整汇总点数及数量，区分大小王，核对总数；由Flash结合牌局自行评估，无需另输出评分。普通牌仅写点数数量；红桃级牌逢人配单列且仍计入该点数总数，不能双计。仅与当前或余手可核对同花顺资源有关的花色，以及通配身份/支付所需花色，保留明确实体信息；复用现有公开绑定/花色资源，不新增宽查询或第二套牌型规则。不得因压缩花色改变canonical、承载或ID；无可核对资源不伪造。
3. 在模型投影层同步撤去由该评分产生的无依据意图，如non_weak默认“控制力稳定/控制牌权”，以及场景标签/模型前建议中的相同评分衍生断言，防止换位置继续注入。人数、控桌归属、公开急迫性、实际支付、公开可行应手及精确剩余分组事实仍可展示。内部评分/影子路由及兼容接口本轮不全面删除：先保持原RAG检索、候选保留/排序、开局快捷路径，隔离prompt改变；明确报告仍有哪些内部消费者，不宣称整个项目已消除所有评分影响。若现有接口使投影无法隔离，先说明具体依赖，避免静默改变候选或检索。
4. 明确语义优先级，而非给字段编造数值权重：合法性/输出契约为硬约束；当前手牌、公开桌面/角色/顺序/余张及已确认历史为事实；实体支付和完整确证计算可用作可核对依据；外部可行应手上界是可能而非实持；M10共同假设/有界结果及pass行为推测有各自不确定边界；RAG和其余本地建议仅作条件化参考。冲突时优先核对事实和计算前提。不同证据的可信度不等同于固定策略收益权重，不能硬性规定清牌永远高于阻断或保炸永远优先。
5. 提示明确“压过桌面不等于以后取得自由领出机会”。支付更强牌应比较相对低成本候选增加的实际争权/阻断/收尾收益与余手损失；若提升缺少支持，考虑低成本清理及pass。保留直接出完、可核对控制续出和公开紧急阻断等反例，由模型取舍。不强制选低牌，不追加固定评分、删候选或模型后置改牌。

尽量在既有位置替换/压缩内容，不另堆一组长解释；本轮保留既有reason协议、私有120字符记录和ACK绑定，不执行旧理由扩写任务。
