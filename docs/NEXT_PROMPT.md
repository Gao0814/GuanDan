## 目标与已确认事实

本轮只改模型输出的简短JSON reason要求，使其足以核对实际选择。当前deepseek_client实际Request要求“20字以内理由”，示例为泛化保控制/减手数；九局116条成功reason中114条不超20字。多数自述的保牌事实成立，却不能说明为什么选更高支付、拆末组或多组顺子，而不是相关低成本动作/pass。这是解释可审计性缺口，不是已确证的模型内部策略根因。

实际请求已有成本/不确定性也可能选高成本动作。不得靠继续增加手牌摘要、固定权重、一律保组/出高牌或成功模型后改牌解决本任务。RAG相关性/详尽性保留随后任务：88/116请求消费记牌经验，普通pass取首会挤掉残局；但末对Q已获残局正文仍拆，不能把RAG当唯一原因。本任务不修改RAG检索、正文、来源治理或经验预算。

## 最小实现与边界

- 在既有输出格式处统一要求短reason说明：实际所选相对一个最相关、实际展示的合法替代，多取得什么可见收益，付出什么成本或依赖什么未知条件。有实质取舍时不能只说两侧共有的“保其他资源/减手数/争牌权”。条件不支持更强结论时允许明确不确定，不要求模型声称一定取得最终牌权。
- reason建议不超过80个Unicode字符，一句或两句即可；仅一个有意义动作或事实不足时可以更短，不编造替代、暗牌、后续机会或完整证明。可以用牌型/动作简述比较，不新增返回字段、解释回调或长思考要求，不强制固定推理模板/额外候选分析。避免示例直接让模型照抄泛化收益。
- JSON action_id仍为原展示合法ID，原字段与解析兼容。现有单行化、最多120字符及截断标记不改；Strict成功传递、agent合法性校验、固定workspace私有model_complete与ACK绑定保持。通用CLI/个人目录/聚合报告不新增自由文本落盘，长reasoning/content仍不保存。
- 不改候选、展示顺序、推荐、记牌、引擎、M9/M10、生产预算或成功模型选择器。解释更具体不等于策略改善；新输出指令本身可能影响选择，不能假定ID不变，也不能因此后置改牌。
