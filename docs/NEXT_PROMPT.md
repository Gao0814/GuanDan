# 下一项 Coding 任务：M3c 用公开应手资源差异改善记牌决策输入

你是 Coding Codex。先读 `AGENTS.md`、适用项目 Skills、`README.md`、`CLAUDE.md`、`docs/PROJECT_STATUS.md` 与 `docs/PLAN.md` 顶部、`docs/INVARIANTS.md`、`docs/CODING_BOUNDARY.md`、`docs/BELIEF_STATE.md`；检查 Git status/diff/HEAD、提交 `309927f`、当前记牌器/引擎只读接口、默认 Botzone factory Request 和相关 tests。本任务仍是**整体记牌器算法优化**；1v1 已确认明牌只是一个分支。M3b 输入闭环已交付，但真实模型请求为 0，不能称为策略收益。

## 目标与实现

在完整合法牌局中，当前摘要会把有不同公开应手资源的候选说成同样“可能接”。可复算例：级牌 2 的引擎 seed `0`、step `0`，只看合法单张时，action ID `5`（3）与 `34`（A）对每家都呈“可能单张/炸弹/同花顺”，没有说明未见牌中高于它们的实体单张资源明显不同。不要对这两个 ID 写特判；改善一般性的记牌推断。

1. 复用或扩展引擎**只读**公开应手查询，对每个待比较候选，从该玩家仍可能持有的实体牌域中计算即时合法应手资源的**有界上界**。至少让单张、对子、自然/逢人配炸弹及同花顺的比较保留有用差异；按物理承载牌多重集去重，避免一个实体组合的多个声明虚增资源。可用紧凑档位（如 0、1–2、3–8、9+）而非长组合清单；若档位不能区分有代表性的高低候选，可调整档位并说明。每家容量必须参与筛选，唯一归属确认后仍用确切手牌。规则生成/比较真值只留在 `engine/`；AI 不自行生成可执行动作。
2. 在最多两组 M3 候选对照中，把逐家即时应手类别和上述资源差异纳入**挑选依据**，而不只在固定路线/牌点/余手评分选完后才计算。优先与公开推荐、紧迫对手及下一行动玩家相关的真实取舍；允许同型（如两张单牌/两组对子）和跨型（如连对/单张）。不必强行让每局都有两组；当两侧风险档位相同且没有余牌用途差异时，不占提示预算重复三人的相同结论。
3. 文案严格区分“公开可行上界”“该玩家确认能接”和“未知”。上界不能说成某人的实际应手数、持牌概率或胜率；`pass` 不作为无牌证据，“现在不能接”不推断后续安全。控制摘要长度，模型成功返回的原始合法 ID 与 `source=model` 不变；不得新增模型后的策略改牌。不要修改 connector、ACK、超时、`.env` 或现场目录。

## 验收与评测

- 用完整引擎合法状态验证 seed `0` 的低单/高单公开资源差异，并加其他有反例的状态：逐家容量排除、未知归属仍有少量资源、对子或炸弹/通配类别、同型资源取舍、连对/单张与队友/对手顺序。状态需包含完整公开历史与可验证守恒，不能靠合成单条动作伪造结论；无差异时应如实显示或省略。保护原 M3b 的 E0/E1/E2、四王、固定六张连对与规则边界。
- 通过禁网默认 Botzone factory 的实际 Request 核对完整合法候选、最终展示 ID、推荐与 M3 对照两端、摘要长度和 fake transport 的原始 ID/`source=model`。与 `309927f` 在相同状态比较记牌内容和输入字节，说明增加的信息是否真正区分路线。不要把请求变长当收益。
- 离线正确性完成后，在**新的、有资源差异且模型有取舍空间**的至多四个状态，对 `309927f` 与本版各调用一次相同 `deepseek-flash`，总真实请求最多 8 次、零重试，密钥/端点只经 `config.py`；不读写 `.env`、不持久化 prompt、模型自由文本或凭据。配置/网络失败则记录实际发送数，不换模型或无限补位。记录两版实际展示候选、原始 ID/牌型、选择是否变化，以及适用时的条件性固定规则续局；选择不变也如实报告，不因此强制模型改牌。
