## 已核对事实与目标

固定 workspace 第 27 局 `games/2026_9_29_16-21-21_000027/` 末步由公开历史与 108 张守恒唯一确认：队友 3 已头游、对手 2 已二游、对手 4 单 6 领出后仅余级牌 `2C`，本家有 `44、99`。原始合法动作是两个不同实体单 9 ID 与 pass。模型等约 54 秒后选 pass；平台结果为本队胜。当前 `analyze_public_endgame` 给三个 ID 的 minimax 值均为 0（规则平）、无唯一保胜动作，因而未本地选择；`format_public_endgame_comparisons` 只在值不同时输出，实际请求重复展示两种普通单 9 与 pass 的关系，未直接提供确认的对手末张点数。规划用公开可重建引擎状态穷举这一步：任一 9 的可达结果包含 `[3,2,4,1]` 规则平和 `[3,2,1,4]` 本队胜，pass 只可达前者；对手用 `2C` 压 9 时仍是平。故“不能保胜”不等于“没有任何获胜续局”，三路保底相同也不代表机会相同；上述胜局依赖对手选择 pass，不是胜率预测。

目标是在**已公开确认且有界可求解的小残局**及时决策。用公开可还原的全部活动手牌和引擎规则，区分三个不同结论：双方最优回应下的保底结果、各条合法续局实际可达到的结果、动作之间的策略等价。完整搜索若证明某路线的保底不低于所有其他路线、可达最好结果严格更好，且不存在未计入项目终局目标的真实取舍，就在模型前选择该路线的原始合法 ID；第 27 局应按此条件选一张普通 9，而不是继续等待模型选 pass。唯一保胜路线、所有路线确定同一终局结果、或所有合法续局都无法获胜且存在确定的最优可达路线，也属于可证明的捷径。不能把“对手有办法令我输”的 minimax 值误写成“任何续局都不可能赢”，不能仅凭各动作 minimax 胜/平/负相同便任选，更不能把可达好结果解释为对手犯错概率。证明不足、搜索超限或存在实际策略取舍时，把可公开确认的外部末张/手牌（必要时保留花色）及有用的条件性比较明确传给 DeepSeek，而不是因为动作值相同就省略。不要给对手剩一张或某牌点加固定强制规则；成功模型原始合法 ID 仍保留。

所有者修正了花色范围：不要以“本家整手没有同花顺”为唯一压缩门槛。当前规则下，普通牌花色对牌型/压制的作用集中在同花顺与红桃级牌逢人配。先用完整实体牌信息计算现有及出后可形成的同花顺路线、逢人配身份与用途；随后普通牌型的模型前描述和候选统计应尽量按点数呈现。普通同点数动作若只是换了一张不同花色的非逢人配承载牌，且出后同花顺机会、通配资源及其他实际策略事实等价，就用可追溯的原始合法 ID 作一个策略代表；即使本家有其他同花顺路线，也可以压缩真正等价的动作。若普通出牌会拆掉同花顺、花色载体不同会保留不同同花顺路线，或会消耗红桃 2 的当前/后续逢人配用途，须按实际原始候选给 DeepSeek 明确的出前/出后资源差异与机会成本；不能把这些可核实的资源损失藏在 rank-only 展示后，也不能将其变成一律禁止消耗的硬规则，紧急阻断、立即出完或更有价值的路线仍由模型权衡。即使 `wildcard_count=0`，承载牌含红桃级牌 `2H` 也不能当普通同点牌折叠。现有 `_action_summary_entry` 在普通候选中仍输出带花色的 `carrier_cards`，`_action_signature` 也因承载花色不同保留重复候选；调整应以实际默认 factory 请求为准，而不是只改一段 prose。底层记牌器保留真实花色，以支持 108 张守恒和外部同花顺判断；不得改引擎 `legal_actions()` 的 canonical 展开、删原动作、伪造 action ID 或把不同资源动作误并。最终展示上限 80，推荐与关系双端闭环。
