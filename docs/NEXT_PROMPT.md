## 已核对事实与目标

M8 `ec910ae262159627c4c244fa556285e966d3bcf6` 已把普通动作的花色等价投影接入默认模型请求；原始 canonical ID、同花顺和红桃级牌资源仍保留。M9 应基于当前代码独立核对这一事实，并在投影后的真实候选链上工作。

当前 `exact_public_hand_assignment()` 只在公开历史与 108 张实体守恒能够唯一确定所有活动手牌时返回牌；`analyze_public_endgame()` 用引擎 `step()` 做有界对抗搜索，目前每个原始 ID 只留下一个最坏情形的胜/平/负值。本地仅在唯一原始 ID 能保胜时跳过 DeepSeek。`format_public_endgame_comparisons()` 又只展示不同最坏值，因此各动作同为规则平时，已确证的对手末张也可能没有明确进入模型请求。

第 27 局末步是具体回归线索：本家 `4H 4C 9H 9C` 跟对手单 6，对手末张由公开守恒确认为 `2C`；两种实体单 9 与 pass 的最坏结果都为规则平，但任一 9 还有依赖对手 pass 的合法本队胜局续线，pass 没有。不能把它叫作必胜、概率较高或平台胜负证明；不要按本局点数、seed 或 ID 特判。

本任务建立可复用的**公开确证残局决策**：

- 一旦公开守恒唯一确认外部当前手牌，在未触发更高优先级的既定合法捷径时，把确证的玩家、实体牌、证据边界明确交给 DeepSeek；即使完整搜索超预算，也不能因没有不同的 minimax 对照而隐去这些已证事实。牌型比较与通配/同花顺仍由引擎判定，不把推断暗牌写成确证。
- 在现有本地 pass、立即出完和公开残局捷径所在的模型前决策链中，复用同一类合法 ID 校验与有界搜索。完整求解可证明某策略路线保胜时及时选原始合法代表；没有保胜路线而**只有一条策略路线存在合法可达本队胜局**时，按所有者偏好选它，即使对手回应仍可使本队负局，文案须明确这是“唯一胜局机会”而非保胜。若所有路线均无可达胜局，但某路线有严格更好的可保底终局，也可在完整证明和唯一最佳路线时本地选择。不同实体 ID 若属于同一已证明的策略路线，稳定选一个原始合法代表，不因 ID 数量重复而等待模型。
- 搜索不完整、公开归属不唯一、历史不一致、超节点/时间预算、或多条真实路线仍需取舍时，及时走现有模型/失败回退；绝不把部分分支结果当作证明，也不在模型成功后改牌。保留 M8 花色等价压缩的有效边界，不把同花顺或红桃级牌资源不同的动作误并。

## 验收

- 用引擎完整牌池构造不同座位与不同牌点的 1v1 明牌残局及反例，与独立穷举或引擎续局真值核对：保胜、唯一可达胜局但不保胜、完全无胜局而保底不同、多个真实胜局路线、两个等价实体 ID、对手正常应手与 pass、终局/接风。第 27 局同构状态应选一个原始单 9 ID；pass 不得被说成有同一胜局机会。
- 覆盖守恒不唯一、历史不完整、手牌过多、节点/时间超限的保守路径。完整确证但搜索不适用时，禁网默认 Botzone factory 的实际请求仍应明确展示对手已证手牌；未确证时不得展示。确保候选不超过 80，推荐与关系引用闭环，fake 模型返回展示中的原始合法 ID 后保持 `source=model`。
- 核对本地捷径与既有强制 pass、立即出完的优先级及决策预算；统计完整引擎样本中的求解/回退和本地耗时，不把局部搜索成功推成一般胜率收益。不要启动真实 Botzone/connector/browser，不发真实 DeepSeek 请求，不读取或修改现场 evidence。
- 运行定向、主规则和适用全量 `unittest`、`git diff --check`。提交前检查有无按本局牌点/ID 特判、重复的本地捷径、仅增加 prompt 文案却不改变有证明残局的及时决策，或把唯一“可能赢”误标为“必胜”。仅提交本任务业务代码/tests；报告实际证据层级、commit、最终 Git status 和当前范围内真实剩余风险。
