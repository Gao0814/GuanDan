# 下一项 Coding 任务：M3b 让记牌器比较逐家应手与实际候选

你是 Coding Codex。先读根目录 `AGENTS.md`、适用项目 Skills、`README.md`、`CLAUDE.md`、`docs/PROJECT_STATUS.md` 和 `docs/PLAN.md` 顶部、`docs/BELIEF_STATE.md`、`docs/INVARIANTS.md`、`docs/CODING_BOUNDARY.md`，检查 Git status/diff/HEAD、`b5daf9f`、当前记牌器/候选筛选/默认 Botzone factory 与相关 tests。本任务是**整体记牌器算法优化**，1v1 已确认明牌只是一个分支。规划 Codex 已复核 `b5daf9f` 修复天王炸与连对长度；上一轮四对真实模型选择均未变，不能宣称策略增益，也无需重跑同一批四组状态。

## 要实现的改进

1. 让多人局的记牌信息对**具体合法候选与具体玩家**有用。基于公开 `observe()`、已验证实体牌池、每家余牌容量、回合顺序和引擎牌型/比较真值，给少量重要候选的即时应手做保守分类：公开条件证明该玩家无法接、唯一归属确认后确有可接牌型、或仍可能/未知。覆盖同牌型应手、炸弹与同花顺等跨牌型应手，逢人配按实体牌与声明分别处理。任何牌型/通配边界算不清时退回“未知”，不得把全场未见牌指认为某个对手手牌，不得把 pass 或行为偏好当硬证据；“不能立即接”也不代表这手最终安全或必胜。区分对手与队友、下一位可行动玩家。
2. 改进模型前对照的**选择与表达**：从实际最终展示的原始合法 ID 中挑最多几组最能体现控制牌消耗、余牌结构和逐家应手差异的路线，允许两张不同单牌、两组对子等同牌型比较，也保留有意义的连对/单张、顺子/单张等跨牌型比较。优先与推荐 ID 和紧迫局面相关的候选，避免现有固定牌型顺序在只有同牌型候选时输出 0 条对照。用精简的逐家结论替换低价值的全场牌池重复文字，给出证据等级和条件，不靠长提示提高表面存在感。最终候选仍不超过 80，关系两端/推荐在实际 Request 中闭环；模型成功返回的展示原始 ID 和 `source=model` 不变，不加策略后置覆盖。
3. 保留 `b5daf9f` 的实体守恒、异常历史 E0、唯一归属 E2 与公开规则只读接口。AI 仍只读 `observe()`/`legal_actions()`，不读取隐藏 `GameState`、不自行构造可执行动作；需要新的规则真值辅助时由引擎提供只读接口并做主规则回归。不要修改 Botzone connector、超时、ACK、`.env` 或真实运行目录。

## 具体验收

- 用引擎生成完整合法局面并核对默认 Botzone factory 禁网 Request。至少包含：某对手公开余牌数不足以打出能接当前候选的任何牌型时的**可证明即时不能接**；余牌数充足但未见牌归属不明时只能报可能/未知；相同牌型两个合法候选消耗不同控制资源；连对与小单取舍；一例队友可接、对手未必可接或反向反例。验证全体可能炸弹类别与通配边界，避免只检查自然同点炸弹。所有者的 `445566` 叙述只能作近似场景，不声称现场复盘。
- 禁网对照 `b5daf9f` 与新版本同状态的实际候选、记牌文字、字符/字节规模和 fake transport 选择闭环；候选正文与引用的 ID 一致，未证明的归属不变成确定事实。若某状态没有真实可区分的候选，不为凑比较数捏造关系。
- 在离线逻辑完成后，可对**新的、有区分力的**至多四个状态做 `b5daf9f` 与新版本各一次真实 `deepseek-flash` 请求，总数最多 8、零重试。两版使用同一进程范围配置和 `config.py`，不读写 `.env` 或输出密钥、完整 prompt、模型自由文本；配置/网络失败则报告实际发送数，不改模型或补位。记录实际展示候选、返回原始 ID/牌型、`source`、选择变化及必要的条件性续局对照。只有输入或选择证据时只报告对应层次的结论；单次改变不能证明胜率，全部不变也不能证明总体无效。
- 运行定向测试、主规则回归、全量 `python -m unittest discover -q` 和 `git diff --check`。只提交本轮自己的业务代码/tests，按精确路径暂存；交回修改、验证、模型请求数、策略证据、当前范围内剩余风险、commit 和最终 Git 状态。
