# 下一项 Coding 任务：M3 记牌器公开事实与候选决策关联

你是 Coding Codex。项目主线是掼蛋 AI 算法；本任务要**改进现有记牌器的实际决策作用**，不是单独开发一对一明牌玩法，也不是继续只做观察。先读根目录 `AGENTS.md`、`README.md`、`CLAUDE.md`、`docs/PROJECT_STATUS.md` 顶部、`docs/PLAN.md` 顶部、`docs/BELIEF_STATE.md` 的 J 系列结论、`docs/INVARIANTS.md`、`docs/CODING_BOUNDARY.md` 和相关 tests；确认 Git status/diff/HEAD。检查 `.agents/skills`，仅在真正适用时使用。不要访问或修改两个 Botzone workspace、启动 connector/浏览器或读取 `.env` 正文。

## 现状与目标

默认 `CardTracker` 从公开历史和本家手牌统计全场外部点数，前期只展示四种关注点数、残局全展示；它不区分持牌玩家或余牌容量，也不把记牌事实用于合法候选间的接管、控制牌保留和收尾比较。文字“当前最大牌”和“除上述可能外不存在其他炸弹”会夸大推断范围。`card_belief`、`card_constraints`、`card_allocations`、`card_signals` 已有公开牌池和硬约束，但默认 Botzone factory 不消费旧 confidence prompt；旧通用边际概率 prompt 的动作质量审计为 `no_observed_action_quality_gain`，不得原样开关启用。

本轮交付一个完整算法改动：复用已验证的公开事实，把**准确、有界、与当下候选有关**的记牌比较放进默认 DeepSeek 模型前输入。四人常规阶段和残局都要有价值；仅剩一名外部未完赛玩家、物理牌守恒且唯一归属确认时，增加一对一已知手牌的更精确分支。DeepSeek 继续决定真实取舍；禁止在成功模型返回后强制替换其合法 ID。

## 实现边界

1. 从 `observe()` 的公开历史、当前本家手牌和其他玩家余牌构造事实。实际打出实体牌以 `carrier_cards` 为准；缺失/异常历史、数量不守恒、牌池不精确时保守降级或省略该项，不能把声明牌、pass 或行为偏好当作确认持牌。区分“已出/本家持有”“外部尚未见”“某家已确认”“某家可能持有”；队友和对手分别标注。修正旧摘要误导文字，尤其普通同点数炸弹与同花顺等其他炸弹的范围，不输出伪精确概率。
2. 在已展示的原始合法候选中做少量跨路线对照。优先选择当前有关的单张、对子、三张、顺子、连对、炸弹等实际存在路线，并说明外部控制资源的已知/未知、对手与队友余牌、出后自己保留的控制牌和余牌结构如何影响“先清组合还是先出小单”的判断。有关比较必须绑定实际展示候选，不能生成、虚构或覆盖 action ID；候选预算与推荐闭环不变。留给模型判断牌权、队友收益和不确定的风险。
3. 当唯一剩余外部玩家的实体手牌由公开守恒确认为已知时，至少给出针对当前候选的即时接管可行性及下一手资源对照；如需要规则演算，只能复用引擎规则真值或增加只读公开规则接口，AI 不接触隐藏 `GameState`，也不自行造可执行动作。非唯一归属、多个未完赛玩家或状态不一致时不得输出“对手明牌”“必胜”。此分支是整体记牌器的一项能力，不要把全部改动限制在 1v1。
4. 模型前文字有明确大小上限和证据等级，避免重复整段历史或淹没候选。保持 `CARD_TRACKING_ENABLED` 现有开关语义、默认 Botzone factory 的其他策略配置、合法动作与 `source=model` 契约。不要改变规则、Botzone ACK、超时、连接器或成功模型后动作选择。

## 验收与评测

- 用引擎构造完整合法的固定级牌 2、四人、无贡状态，至少覆盖：四人中局公开记牌改变控制牌判断；多人残局未知归属；唯一归属的 1v1；牌池不精确/容量矛盾的降级；一例连对优于小单的条件与一例相反条件。所有者叙述的 `445566`、两张单牌含小王、对手约六张且可能握大王可作为**近似场景**，不得声称复现了缺失的现场逐动作记录。反例要防止记牌输入恒推连对。
