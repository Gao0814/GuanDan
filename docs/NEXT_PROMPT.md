## 固定设计

1. 在任何真实请求前，用引擎和两版实际生产 factory 禁网扫描未用 seed 区间，按升序取满足条件的**首两个**状态：`150000..150799` 中完整初局 raw 候选 `>80` 且完整对子/单张、通配资源关系均存在；`151000..151799` 中完整初局 raw 候选 `<=80`、至少有单张/对子/三张三类实际合法动作；`160000..160799` 的规则 AI 续局中首个中局本家模型决策，分别取一个有公开压力/资源取舍关系、一个有队友或危险对手关系的状态；`170000..170799` 的规则 AI 续局中首个残局本家模型决策，取两个不同 seed、至少两个非 pass 合法候选的状态。八个状态必须彼此不同，两版都真实走模型，公开 observation 与完整 canonical legal actions 逐字段一致；没有合格状态就停止并报告该层缺口，不换区间或降低门槛。选择只看公开状态与完整关系，不能看模型输出或代理好坏。固定 seed、step、状态摘要哈希、两版 HEAD、非敏感模型控制设置及选取理由后才可发请求。
2. 对每个冻结状态先跑两版禁网 fake transport：核对实际 Request 的 canonical ID、推荐闭环、80 项上限、来源 B/C 适用、完整关系分母/双端可见/渲染句、各牌型与通配占用、prompt 长度、组装时长和合法返回保真；生产本地直选状态不得混入模型配对。H3-A9 `opening_2` 是反事实历史样本，继续从生产汇总隔离。真实请求前须完成全部 16 个版本状态资格；任一同状态、配置或请求契约不一致就停在离线结果，不选择替补好看的状态。
3. **仅在项目所有者已明确批准本任务最多 32 次真实请求后**，每状态对两版各调用两次：8 状态×2 版本×2 重复，零自动重试、零替补调用。相邻配对交错，奇数状态按 baseline/current/current/baseline，偶数状态反序；两版同一模型、温度、超时与 119 秒整次预算。每次已发出的请求计入总上限；超时、失败或不合法结果记录固定分类，不重试、不把 fallback 当模型成功。若 API 预检不可用，零请求结束并报告。沿用已验证的生产 SSE/default transport/`urlopen` 计数与正文绑定审计；不得持久化或输出 prompt、请求 URL、凭据、模型响应/reasoning 或异常正文，只保留低敏状态哈希、动作 ID、source、固定结果、单调时长和聚合。
