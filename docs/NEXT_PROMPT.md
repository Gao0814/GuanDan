## 目标与事实

实现所有者采纳的局内行牌分析下一项：把外部玩家三带二携带对子这一公开行为，在有用的当前应手中转化为有依据、可撤回的结构解释。分析同时适用于队友/对手，服务本队走牌与牌权，不能从带出小对直接断言剩下有大对。

- 当前card_tracker已验证公开实体牌池/逐家容量，投影候选相关pass；A区分末手强负向与普通护组/让牌、后接更新。c02db61统一以引擎验证绑定后比较同型强度，声明/承载不同的等强动作不再遗漏。复用此事实与不确定信息的层次，不另建局内/跨局猜牌系统。
- 现有exp_soft_triple_pair_gradient_001只比较本家自由领牌时同三张主组、至少三种自然携带对子路线；它不分析他家历史，也不能证明其余牌。RAG的本家candidate_requirements与外部行为适用条件不能混用。
- 所有者提出“常带较小对子清理”作为待检验行为倾向；旧来源第73条另举多对子时带中间对子、保留大小对子回手的例子。两者是竞争解释，不是相互排斥的固定规则。外部真实备选对子未知，不能把公开携带对子称为当时最小或中间对子。
- 第73条来源是既有candidate_smzdm_strategy_100_001（https://post.smzdm.com/p/a5xk3dpl/），原作者资质未核实；原文组牌例子与项目对外部行为的推导分别登记。网页不可用不编造独立核验或新来源；现有正文/定位与Planning已核对内容可作线索，缺证据如实标明。来源治理字段不进入模型prompt、检索评分或牌域。

## 最小实现范围

1. 在已核验的本局公开历史/实体变化流程上提取相关三带二事实：玩家与队友/对手角色、动作时点、公开声明的主三张/携带对子、当时余张与后续已出实体。解析和声明/承载关联复用引擎公开接口与现有机制；区分自然携带、通配参与和无法唯一解释的承载，不把逢人配声明当自然实体对子。记录事实不等于知道当时所有备选组合。
2. 条件化表达：在清理较小对子这一行为假设下，可弱地支持保留其他较大对子路线；但只有该对子、带中间对子留大小回手、拆组/组合重叠、通配成本、立即出完或紧急应手等也可解释。按实际必要条件给简洁竞争解释，不堆完整口诀清单，不赋未经校准的概率/分数，不将“可能”改成确证。当前牌池/余张不支持的路线由已有可行性事实说明，不能用习惯新增硬排除。
3. 推测必须随公开后续动作更新：后来打出较小对子可推翻“此前一定带最小对”，但不证明现在仍有其他对子；出牌后原实体已扣除，旧推测影响应减弱。已出完、已公开确证、不完整历史或无相关当前取舍时，不继续拿旧行为猜牌。A末手pass和确证事实优先，弱携带习惯不得抵消它们。
4. 只在当前合法动作对照确有价值时消费（例如送队友对子、对手对子应手/争权及三带二后可能的对子回手），结合现有逐家容量/应手证据、本家即时清牌和资源成本；动作仍由DeepSeek裁决。队友/对手使用同一行为事实，不做专用座位/牌点/ID分支。
5. 信息沿既有记牌摘要、应手对照及RAG进入默认factory，确保没有被本家候选条件或经验选槽静默挡住。优先修订/复用现有机制；如确需一条独立软经验，必须说明其外部行为条件为何不同于本家梯度，避免重复条目与并行统计器。保留原本家梯度适用语义，不通过无条件放宽它制造“已接入”。摘要稳定有界，不用自由历史长文本取代结构信息。
6. 不改规则、legal/canonical、展示候选/原ID、硬牌域、成功模型动作或M9确证/目标。M10共同假设、样本数/预算/推进/数值保持，不因弱习惯删除、重抽或加权世界；只有确需解释时复用当前行为摘要，避免再算一套续局。递归性能优化另轮，不提高预算。
