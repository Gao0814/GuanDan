## 如何判断与交付

成功返回必须有完整结束与原legal/展示ID闭环；用当前公开引擎绑定/已有资源计算比较实际支付、保留完整组与余牌的变化。必要替代包括pass、原普通应手、完整炸弹及可见同花顺；不要把保炸、低单或高对固定为正确答案。分别核对争权强度、清牌与拆组成本、未来路线是否需要机会，以及两个动作共有的优点能否解释选择。

同次短JSON reason在内存按完整语义审查，给必要脱敏“自述依据→公开事实→替代差异”摘要，包括否定/条件/保留的是哪类资源；不只存关键词标签。不打印或保存新原始响应、自由reason/reasoning_content、完整请求、完整本家手牌或异常正文；既有私有reason只读，缺失就未知，不补造或追加请求。长推理不作为需要保留的证据。

报告四对原ID/动作/实体变化、关键短reason语义、成功/失败与实际调用数。A原body的新返回不等于原局思考；温度0也会波动。单对变化只支持诊断信号，未变不证明摘要无效，不以五局比例或一两次选择声称因果退步、稳定改善或胜率收益。

结果应明确下一步是否有证据支持收缩新增摘要、恢复被替换的关键旧信息，或改进有限成本代表/RAG相关性；有新增反例则说明，不直接执行后续生产修改。重点指出新增摘要给了哪些真实增量、替换掉了哪些与当前选择有关的既有信息，而不是仅比较字数。范围内无具体收益证据时如实收口，不再请求追加样本或泛泛要求所有者继续打。

无需全量或机械重跑已通过套件。禁网检查隔离/合法映射与必要实体支付即可；最后git diff --check、status/HEAD，说明真实剩余限制与任何保留的外部修改。没有生产改动、原证据/现场保持为本轮交付条件。
