## 首版复审发现的缺口

M9 已实现完整可达终局搜索、公开确证手牌模型前摘要，以及唯一保胜或唯一胜局机会的模型前捷径。第 27 局保存的公开状态经规划只读复算，新版能在模型前选原始单 9 ID；此部分保留。

当前 `select_proven_endgame_action()` 在两条以上**不同策略路线都已完整证明可保本队胜**时返回 `None`。规划从 60 个引擎完整续局 seed 中找到 10 个没有立即出完捷径、却有多条保胜路线的小残局。seed 13 step 99 是可复现例：仅两条原始合法动作，保底均为本队胜；其中一条的所有合法续局也只到本队胜。现有默认 Botzone factory 禁网请求仍调用模型。这是完整终局已经证明仍等待模型的机制缺口，不是模型选择好坏问题。

在 M9 **同一任务内**修正搜索与选择：按真实规则把某一原始合法首手的保胜性严格证明后，立即选它，不要求保胜路线唯一，也不继续枚举其他首手或比较它们的可达终局。保胜证明须覆盖该首手下所有相关对手应手和队伍轮转；搜索预算耗尽前仅看到一条可赢续线不构成证明。可以采用安全的证明优先搜索或等价机制，保留有界节点/时间限制。不能为追求另一条“更优”保胜线重新引入模型等待，也不能把不同保胜路线强行标成同一 M8 花色等价类。

只有不存在已证保胜路线时，才判断“唯一可能赢”：必须完整排除**其他所有首手**的本队胜局可达性，其他首手可为规则平或负；该唯一首手只证明存在合法胜局续线，不能称保胜。若仍有多条非保胜胜局机会且有真实取舍，交 DeepSeek。对无胜路线的保底比较也只能使用足够完整的证明。局面不一致、目标路线尚未证成或预算超限时，不得把探索中的部分结果当作本地直选依据；已独立完成的保胜证明可以直接使用，不因其他路线未搜完而作废。选择始终返回原始合法 ID；成功模型动作不后置改牌。不凭牌点、seed、ID 或未经证明的概率写策略特例。

## 验收

- 用 seed 13 step 99 和至少一个不同牌点/座位的完整引擎同类状态，核对独立续局真值、所选原始合法 ID 与默认 factory 禁网路径：有一条严格证明保胜的路线时模型请求为 0；多个等价实体 ID 或多条不同保胜路线不造成模型等待。另以受控预算/计数验证：首条保胜证明完成后不再搜索后续首手；后续首手即使很大或将超限，也不使该证明失效。优先级仍让强制 pass、立即出完先处理。
- 反例覆盖仅找到一条可赢续线却未证明保胜、多条非保胜胜局机会、唯一可能赢但其他路线仅能平、公开手牌不唯一，以及证明完成前节点/时间超限；这些状态不得误选为保胜。“唯一可能赢”只有在其他所有首手均已完整排除胜局时才可本地选。已交付的确证外部手牌在搜索不适用时仍进入实际模型请求；M8 的同花顺/红桃级牌资源差异、候选最多 80、推荐和关系双端闭环、成功模型原始 ID/source=`model` 保持不变。
- 运行定向、主规则和适用全量 `unittest`、`git diff --check`；记录本地捷径耗时与禁网请求计数。不要发真实 DeepSeek 请求或运行 Botzone/connector/browser。提交前检查是否只是增加当前 seed 的特例、是否把未保胜机会说成保胜、是否改变公开信息或模型成功选择契约。仅提交本任务业务代码/tests，报告 commit 与最终 Git status。
