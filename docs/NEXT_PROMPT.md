# M5 Coding：公开 pass 软证据与已知手牌有界多步推演

先读 `AGENTS.md`、适用项目 Skills、`docs/CLEAN_HANDOFF.md`、`docs/PLAN.md` 顶部、`docs/INVARIANTS.md`、`docs/CODING_BOUNDARY.md`；核对 Git status、HEAD、相关提交、代码和测试。只提交本任务自有业务代码与 tests，不混入规划文档或外部改动。本任务不启动 Botzone、connector、浏览器，不读取 `.env` 或两个现场 workspace；真实页面操作仍由所有者完成。

## 已确认事实与目标

`agents/card_belief.py` 当前只记录每家 `pass_count`；`agents/card_constraints.py` 不用 pass 缩小硬牌域。M3 记牌在多人局给出公开未见牌/余牌容量上界，唯一外部持牌人时核验即时应手；`agents/short_endgame_planner.py` 的 1–8 张分析只求本家在以后重新自由首出时的最少分组，不搜索对手回应、pass、轮转和终局。它们均未证明导致过往现场选牌或首局负局。

本次交付一个可复用的**公开历史推断与有界局面推演机制**：让 pass 在多人局为模型提供有条件、可撤回的持牌/应手假设；当所有活动玩家手牌由公开守恒唯一确定时，利用规则真值进行多步推演，减少能被可靠解决的小残局的模型等待。不可用或超预算时保留当前模型路径，不以某个 seed、牌点或现场截图定规则。

## 实现边界

1. 先核查公开 `history` 是否足以重建每次 pass 的当时桌面约束、领出者、行动座位、队伍与后续公开动作。只对可验证片段形成软证据，使至少一类候选的逐家应手风险比较真正随相关 pass 历史变化，而非仅重复打印 pass 次数；pass 可能是保留控制牌、让队友领牌或确实无应手，**不能**据此删掉物理上仍可行的持牌分配、宣布某家绝无应手，或虚构概率。若使用数值概率/权重，须说明其经验依据并用未参与调参的完整引擎牌局核对校准；证据不足时只给定性、带反例的假设或完全省略。现有 108 张守恒、玩家容量、E0/E1/E2 硬事实不因软推断而降级或改写。
2. 在公开信息确实唯一确定全部活动手牌、规则状态可复建且余牌规模可控时，做有界的多步行动比较，至少覆盖真实跟牌、pass、牌权重置、行动顺序和终局。复用 `engine/` 规则真值或增加必要的只读纯接口；AI 不读取/修改实际引擎内部状态，也不在 `agents/` 重写一套牌型、压制和状态推进规则。设明确的本地时间/搜索量上限；无法证明结果或超限时退回现有模型决策。只有无需未知牌假设且可证明的唯一无取舍行动，才可在模型调用前选原始合法 ID；其余搜索结论作为条件性候选比较交给 DeepSeek，绝不在成功模型后改牌。
3. 将有效软证据和推演比较接到默认 Botzone DeepSeek factory 的实际请求与有限候选中。比较引用的 action ID 必须来自完整 canonical 合法集合且两端实际展示，最终候选仍最多 80；不以更多提示文字代替候选闭环。普通起局与不适用的局面不应因推演显著增加本地组装时间。不得保存或报告模型自由文本、私密配置和现场完整 prompt。

## 验收与报告

- 用引擎生成的完整四人牌局和不同座位验证 pass：包含对手 pass 后确实无应手、对手或队友**持有可压牌仍选择 pass**、历史不完整、随后公开动作推翻早先软假设。测试只在评测侧读取其他玩家暗牌作真值，生产推断只用公开 payload。对多局非特制状态比较新旧软推断的覆盖和误判；不能只锁死单个正例。
- 用多个合法小残局（至少含已知手牌 1v1 和不同跟牌/接风边界）验证多步结果、原始合法 ID、超预算/歧义退回，并与引擎真值对照；证明它是轮流推演而非“本家剩余最少分组”的换名。对密集起局和触发推演的残局测本地耗时，报告上限与模型调用是否实际减少。
- 用默认 factory 禁网 Request 验证证据标签、候选/推荐/关系闭环及成功模型返回原始合法 ID/source；跑相关定向、主规则与全量 `unittest`、`git diff --check`。可在离线资格通过后，对预先固定的同状态正反例做总数**严格少于 10 次**、零重试的真实 `deepseek-flash` 请求；若配置或请求条件不符、或发现所有者的项目 connector 正在运行，则不发，明确模型实际验证为 0，不影响离线实现交付。不得停止所有者进程。真实选择仅作方向性观察，不声称胜率。
- 最终报告根因确认层级、统一实现与反补丁自检、完整牌局和时延数据、实际模型请求数、未解决限制、commit 与最终 Git status。不要为等待更多现场局数而把本任务拆成纯资格或日志阶段。
