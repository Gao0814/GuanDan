## 生产实现

1. 复审从完整 canonical 候选到默认 Botzone `build_agent_factory("deepseek")` Request 的全链路。对有来源/公开结构意义的关系建立**预算内成对选择**：保留立即出完、合法 pass、推荐、跨牌型/通配代表及必要压制动作；其余关系按当前可见候选、来源适用、公开余牌差异、与推荐/主要路线的关联和新增双端成本进行稳定、可解释的取舍。优先覆盖不同类型的真实比较，避免同一密集 family 或大量相似通配变体耗尽 80 项。单一动作可参与多条关系，选择时利用共享端点；任何进入 prompt 的关系必须两端都在最终原始候选中。不能为了提高分数而删除困难关系、改变分母或构造虚拟可选动作。
2. 对最终可见的单张、对子、三张、顺子、炸弹及通配替代路线，给模型前提示清楚、紧凑的出后剩牌用途和取舍/可推翻条件；只用公开 observation 与 canonical 动作。B 级原则需满足正文核对的牌力角色、减少孤张/余组、控制与回手等条件；C 级仍为可撤回软假设，不因出现候选就一律加入。无适用证据时留空，不凑条目；来源作者/等级/URL 等治理字段不得进 prompt 或检索评分。估计余组不得冒称精确未来出牌手数。
3. 审视本地公式能否从完整公开关系中找到新的、B 级可支持且可反证的**真实**安全路线；若没有，就保持 fail closed 并给出代表性阻断分类。不要在同一局有多条不等价余牌路线时按 ID/花色任意选牌；不要把中性对子/三张的意图表述当作必出令。成功模型返回的展示候选原始 ID 和 source=`model` 必须原样保留。
