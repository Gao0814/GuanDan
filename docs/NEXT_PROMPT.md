# Coding Codex 执行 Prompt：所有者连续试局与跨启动最近 10 局记录

## 已确认需求

所有者亲自启动 `scripts/run_manual_botzone_batch.cmd`，由其在 Botzone 页面逐局操作。脚本启动后，**单个 connector 持续轮询并在暂时断线时继续尝试重连**；第 10 局不自动停。所有者按 Ctrl+C 或关闭窗口才主动结束。平台或网络不能保证每一秒都显示“已连接”；不可恢复的配置/协议故障仍须明确报错，不能伪装成连接正常。`--games N` 表示保留最近 N 局的容量，默认 10，不再表示自动停机数。

逐局记录须**跨脚本启动延续**：新启动先读取既有滚动记录，再在后面加入新局；不足 10 局不清空旧局，满 10 局后每新增一局移出最早一局。所有者还明确要求新版首次启动把**当前旧批次**已有的可核验逐局记录纳入窗口；原始旧批次目录保持原样，不能在其仍运行时读取、迁移或改写。首次导入须幂等，不能重启一次就重复导入一次；只从固定 `D:\VsCodeProject\BotzoneWorkspace` 中身份明确的旧批次导入，含糊时报告并允许指定精确目录，不猜测、不扫描或清理其他 workspace。

新局用本机时间到分钟标记，展示格式例如 `2026_9_27_23:33`。Windows 文件名不能有 `:`，实际每局文件/键使用等价安全形式 `2026_9_27_23-33`，同一分钟多局再加稳定序号防重名；记录内保存原展示时间及本地时区。旧 `game-results.jsonl` 没有逐局时间，导入时必须标注时间未知或仅有导入时间，不能伪造为历史对局时间。

当前实现每次新建 `manual-batch-*` 子目录，`game-results.jsonl` 只追加，10 个符合条件的完局后退出，且默认 cycle/wall 上限随 `--games` 增长。这四点都与新需求不符。所有者最近一局中途终止，页面“等待重连”后又“已连接”；尚无证据区分页面 120 秒设置、模型等待或连接问题。本任务不把该局归因任何一方，不运行真实 Botzone；旧现场证据只在所有者结束当前批次并交付后另做只读审计。

## 实现边界

先读 `AGENTS.md`、适用文档、相关代码/tests，查 Git status/diff/HEAD。以最小必要改动实现一处**受管理的持久滚动记录区**，与每次运行的新 state/audit/streams 目录分开。只滚动此新记录区内的逐局项，不修改旧批次文件，不碰 `D:\VsCodeProject\GuanDanManualWorkspace`。进程占用保护、`deepseek-flash`、动作选择、ACK 事务、模型期限与合法动作契约保持现状。

1. 单 connector 在 idle、重连和局间持续工作；取消默认按完局数及默认 cycle/wall 上限退出。只有所有者显式设置的上限才按上限结束；可恢复的传输失败继续有限退避重试，不把“窗口仍开着”误报为页面持续已连接。不可恢复错误用固定低敏类别报告，不吞掉故障。Ctrl+C 尽量正常收尾；关闭窗口可能立即终止，因此每条已完成记录在写入时就要持久化。
2. 最近 N 局记录跨启动持久化，按真实先后顺序滚动，保留总局序号而不重编号。明确终局且符合原 ACK/四人条件的胜负、平及平台错误按真实固定类别记录。对**已观察到开始、但未收到可确认终局**的异常局，可在下一局开始或进程结束时以“结果未确认”占一个窗口位置；不能因暂时“等待重连”就宣称该局结束，也不得编造胜负。若公开事件不足以判定结束，保留未确认状态和可审计阶段证据。聚合 audit 与最近 N 局窗口分别标注累计值/保留值；当前运行中的旧批次不得因新代码而改变。
3. 首次导入当前旧批次中能验证的结果行，顺序与去重正确，旧文件原样保留；没有独立时间或没有结果行的历史局不能补造。每次新启动读取同一滚动区并接续编号；导入后满 10 的第 11 局移出最早一局。真实写入失败不影响出牌或 ACK，但必须报告记录不完整。低敏记录中不得存连接 URL、密钥、prompt、模型自由文本或 match ID。

禁网测试覆盖：跨两次启动从 7 局续记到 12 局只保留第 3–12 局；同一分钟命名不冲突；首次旧批次导入只发生一次且旧文件字节不变；未确认异常局不编造成胜负；idle/暂时重连后不自动退出；第 10 局不停止；Ctrl+C、显式上限、写入失败与校验。运行相关测试、适用主规则回归及 `git diff --check`。不要启动真实 connector、联网 preflight、Botzone 页面、浏览器或 DeepSeek 请求。

只提交本轮自身业务代码/tests，不改规划 docs、`.env`、封板或仍在运行的旧证据。报告实现的“最近 10 局”口径、首次导入的可靠范围、验证、commit 与最终 Git status。真实连接和跨局行为由所有者后续亲自验证。
