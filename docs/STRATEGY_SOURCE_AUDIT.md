# 掼蛋策略知识来源审计

## 1. 审计结论

H3-A0 之前，`rag/experience_corpus/basic_human_experience.md` 的经验条目没有独立来源治理，旧开局公式的点数阈值与固定权重也缺少来源或校准。此问题后来由 provenance registry、来源化语料和窄开局公式部分修复；当前任务是把已核对材料中尚未落地的条件化打法继续整合，而不是把旧自拟启发式重新包装为专家定式。

seed `47004` 当时的自由首出 Q 不是一个只需微调分数的孤立反例。它暴露了旧公式把自拟权重当成稳定经验的问题。后续策略调整必须沿已建立的来源链，把自然语言原则转成公开输入上的可测试关系；不再按单局动作逐条补丁。

## 2. 来源等级

| 等级 | 用途 | 可否直接激活策略 |
|---|---|---|
| A：官方规则 | 规则、牌型、比赛口径、术语 | 只能支持 `engine/` 与规则 RAG，不能证明策略优劣 |
| B：具名专家或正规出版社完整内容 | 组牌、角色、领出、配合、回手、残局等人类经验 | 正文明确支持的定性原则可作为条件化软策略直接激活；本地快速路径仍须公开条件明确并经过 fixture 验证 |
| C：可追溯但方法不完整的公开经验 | 口诀、转载文章、平台攻略、未披露样本的统计 | 经项目所有者批准后，定性原则可作为明确标识、可撤回的软策略假设进入 RAG/prompt；不得采用无方法统计、不得单独驱动本地动作 |
| R：学术与数据驱动研究 | 架构、训练、动作约简、评测方法 | 可指导系统设计；不能自动当作具体出牌定式 |

冲突时固定采用：规则真值 > 原始 canonical actions > 已验证的高等级策略原则 > 低等级候选。任何经验都不得裁决合法性。

## 4. 对现有决策链的约束

1. `engine/` 与规则 RAG 只采用项目规则真值和已核对的规则口径。
2. 经验 RAG 的知识正文只保留策略语义和场景标签。独立 provenance registry 通过稳定条目 ID 记录来源等级、作者/机构、定位、适用范围和状态；这些治理字段只供加载过滤与离线审计，不参与检索评分、冲突扫描或模型 prompt。无 registry 映射或未激活条目不能进入模型，也不能伪装为人类共识。
3. 公式化开局只承载高置信、边界清楚、可用公开输入验证的人类定式。遇到来源冲突、上下文不足或没有明确公式时返回“不适用”，交给 RAG + DeepSeek；不得用更多神秘权重掩盖不确定性。
4. 剪枝以召回为目标，至少保留有代表性的合法牌型和原始 ID。它可以控制预算，但不能因为某条经验偏好单张就删除全部对子。
5. RAG 输出软策略依据，DeepSeek 在可见的 canonical 候选内选择。不得恢复成功模型后的策略动作覆盖。
6. 每条外部经验先转成关系型 fixture，例如“强控制且有回手资源时，结构安全的小单不应输给无理由消耗的较高普通单张”。B 级明确原则可直接进入条件化软提示；C 级定性内容只能以 `soft_hypothesis` 激活。只有公开条件明确、跨多个变体稳定且不依赖动态协同时才可进入本地快速路径。
7. 真实 Botzone 单局只用于发现反例和验证运行链，不能证明一个套路普遍提高胜率。策略收益仍需固定样本、消融或成对评测。
