# Botzone游戏与出牌审计

面向所有者已自行打完并留证的游戏，回答实际发生了什么、当时模型能看到什么、选择是否有合理依据、是否需要Coding修正。采用根AGENTS的现行规则/职责/隐私边界，不复制现场托管、正式实验或清理流程。

## 选择证据

- 用户指定局面就优先定位该局/决策；“刚打的一局”按现有按局目录时间和状态定位，不能只凭最后修改的文件猜局。“最近N局”只读取需要的N局，排除运行中和无明确正常结果的局用于胜负比例，但可保留其已确认动作作诊断。证据不够只请求缺少的局/时点，不重新启动游戏。
- 默认固定根是 `D:\VsCodeProject\BotzoneWorkspace\games`；用户交付个人目录证据时以其指定目录为准。先核对目录普通非链接属性和当前证据格式，读取manifest、decisions、timeline及相关requests；按疑点读必要段落，不每轮整库扫描、全量审计或重复既有检查。
- 当前按局文件可记录待确认动作。将最终原始ID/action与当次原canonical集合、实际展示集合及后续ACK对应；不能仅凭decisions记录、source=model或request_prepared断定模型成功、请求送达、真实出牌已确认。重试、多次请求和仅pass/直接出完的本地路径分别识别。

## 还原决策与合理性

从当时公开payload还原桌面动作、同轮历史匹配的实际控桌玩家、队友/对手关系、余张、行动顺序和已出完状态。完整模型请求存在时在内存读取，检查它实际包含哪些提示、候选和推演；当前代码能生成某提示不证明旧请求已发送该提示。

比较所选动作与必要的合法替代：普通应手、pass、炸弹/控制单张等。复用当前资源/结构计算，按真实carrier扣牌检查自然炸弹、同花顺、对子/三张或控制资源的前后变化，避免重复自建规则或统计器。“没有使用炸弹牌型”不等于“保住了炸弹实体”；重叠组合不算多份独立资源。只为疑点增加能改变结论的少量禁网诊断。

模型解释是当次自述，必须与实际动作和公开事实分别核对。简短JSON reason、API reasoning_content、模型前策略建议、本地回退理由是不同来源；缺失就写未知，不用后续出牌或重放生成原局动机。关键词命中只能说明概念提及，否定、假设、历史回顾与当前陈述须分清，不能据摘要直接判事实幻觉或断定因果。

对持炸pass核对当前是否队友控桌、对手公开紧迫性、可用应手和资源损失；让牌符合协同解释不证明实际名次收益。对拆炸核对是否立即出完、确有紧急阻断或可见重组收益；不把单局胜负用来证明每手合理，也不制定固定牌点/ID特判、“一律不拆”或“有炸必压”。

M9严格公开确证、M10共同假设和有限深度、静态余手分组分别判读；有文字不等于完成严格搜索或得到胜率/减时收益。计时明确范围，缺少模型前后对照就不能宣称推理加速。

## 必要时重放

只在当前任务需要真实重放且授权满足时使用API；不因普通审计自动调用。先确定有限调用预算，使用保存的原body、原展示与原legal集合，异常和重试计入预算。温度0也不保证同一输出；重放反映新请求，不恢复原局思考。改过提示的诊断须另列，不能混称原请求复现。

不打印/复制私有body、完整手牌、原始模型响应、长推理、凭据或连接信息；低敏报告只给必要ID/动作类别、状态、资源变化和允许的简短解释摘要。原证据不修改或清理，不启停connector。没有原响应时，审查执行脚本与原输入只能确认方法和映射；实际HTTP结果/解释仍明确标为执行报告证据，不能声称独立重验过模型返回。

## 交付与推进

先回答用户具体疑点，再列已确认事实、待验证声明和根因假设。最近多局按有效完局报告胜/平/负和异常，规则结果与平台积分分开；小样本只作方向性观察，不冒充因果收益。

若确实需要Coding，Planning维护一个当前 `docs/NEXT_PROMPT.md`，写明可复现场景、已确认缺口、必要不变量和有判断力的验收；不要只停在建议，也不要先把猜测写成根因或执行策略修改。若需要所有者先操作，说明具体操作并保留证据，结果明确后才写依赖该结果的Prompt。完成的Prompt撤下或由确定的下一任务替换；状态文档精简更新，不新增每局报告堆。
